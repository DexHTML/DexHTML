# DexHTML

## Внутренние цифровые системы · Автоматизация процессов · Digital-проекты

В свободное от основной работы время развиваю цифровые инструменты для реальных рабочих и пользовательских задач: внутренние web-системы, автоматизацию процессов, Telegram-продукты, SEO-MVP, медиа- и контентные проекты.

Мой подход:

**задача → рабочий процесс → структура данных → пользовательский сценарий → реализация → проверка → внедрение → развитие**

Особое внимание уделяю постепенным изменениям, сохранности данных, проверяемости бизнес-логики и тому, чтобы система оставалась понятной пользователю.

# Основные внутренние системы

## TechRepair — учёт техники и ремонтов

**Действующая внутренняя система с проверенными сценариями установки, восстановления и обновления.**

| Продукт | Инженерная основа | Текущий этап |
| :--- | :--- | :--- |
| Оборудование, QR, ремонты, подменный фонд, акты и отчёты | Контроль данных, роли, миграции, резервные копии и автоматические проверки | Кандидат `1.0.0-rc.1` прошёл полный CI; финальная релизная приёмка впереди |

TechRepair сохраняет историю устройств, их размещения и ремонтов. В работе помогают массовый приём, QR-выдача свободной подменной техники, светлая и тёмная темы. Инженерная часть включает защиту сессий и запросов, контроль целостности БД, аудит изменений, безопасные обновления и CI с проверками по уровню риска. Для внутренних интеграций предусмотрен API только для чтения; Windows Setup использует проверенные серверные сценарии Linux.

## FairDesk

**Рабочий внутренний MVP системы заявок и распределения задач**

FairDesk отвечает за workflow заявки:

- роли заявителя, исполнителя и администратора;
- категории и рабочие группы;
- ручное и автоматическое назначение;
- общую очередь для отдельных сценариев;
- комментарии, историю и архив;
- аудит;
- объяснение логики назначения;
- интеграцию с данными техники и доступности сотрудников.

FairDesk не копирует ответственность соседних систем: данные о технике остаются в TechRepair, а календарь и availability — в Duty Schedule.

Подтверждён реальный integration path через Django-клиент FairDesk и Duty Schedule API v1.

[Подробнее о FairDesk](case-studies/FAIRDESK.md)

## Duty Schedule — графики дежурств и доступность сотрудников

**Действующая внутренняя production-система с исторически корректным планированием.**

Последний выпущенный релиз: **2.0.4 — released / accepted**. После него внедрены дополнительные проверенные улучшения надёжности и безопасности.

Возможности системы:

- управление жизненным циклом сотрудников, включая переводы, завершение работы и возвращение;
- состав групп и режимы работы **с датами действия** — без переписывания прошлых месяцев;
- версионируемая очередь дежурств и независимый порядок отображения;
- производственный календарь, отпуска, больничные, обучение и другая недоступность;
- дежурства, компенсационные дни и контролируемые ручные корректировки;
- Today, месячный Preview и Month Check;
- динамический Excel без фиксированного числа сотрудников;
- единая расчётная модель для интерфейса, Excel и API v1;
- read-only интеграция с FairDesk для назначения задач по доступности;
- роли, CSRF, контроль сессий, журналирование, миграции и восстановление;
- регрессионные проверки исторических и пограничных сценариев.

Последняя подтверждённая эксплуатационная проверка внедрённой линии: **249 проверок · 0 предупреждений · 0 ошибок**. Новые изменения, ожидающие приёмки, не включены в публичное описание как готовые функции.

## Как связаны внутренние системы

Основные модули развиваются как независимые источники правды:

- **TechRepair** — техника и ремонтная история;
- **FairDesk** — заявки, workflow, исполнители и нагрузка;
- **Duty Schedule** — календарь, дежурства и доступность сотрудников.

Интеграции строятся через ограниченные read-only контракты там, где один модуль должен получить данные другого. Это позволяет развивать системы независимо и не превращать их в один монолит.

Исходный код, рабочие данные и внутренняя инфраструктура этих систем остаются закрытыми. В профиле публикуются только безопасные case studies.

# Как я работаю

При работе над проектом стараюсь сначала понять:

- какую реальную проблему он решает;
- кто будет им пользоваться;
- какие данные и бизнес-правила критичны;
- какой пользовательский сценарий должен быть простым;
- что нужно доказать тестами до внедрения;
- где проходит граница ответственности между системами;
- какие данные помогут принять следующее решение.

Предпочитаю постепенное развитие:

**анализ → небольшой шаг → проверка → фиксация результата → следующий этап**
